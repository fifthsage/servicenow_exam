홈 CIS-DF 홈 연습 퀴즈

개념정리

서비스나우를 처음 접하는 사람도 시험과 실무 맥락을 동시에 이해할 수 있도록 구성한 블루프린트형 스터디 가이드입니다. 핵심 개념, 실제 역할, 그리고 영어 지문 키워드를 함께 보면서 빠르게 정리하세요.

이 페이지의 흐름: 1) CMDB 목적 2) CSDM 구조 3) 클래스 모델 4) IRE 원리 5) 품질/거버넌스 도구 6) 시험 문장 패턴.

CMDB 가치와 3대 기둥 CSDM 구조와 도메인 CI/Asset/클래스 모델링 IRE 식별/조정 Data Foundations/거버넌스 실전 문장 패턴

1. CMDB 가치와 3대 기둥

CORE

우선 CMDB가 왜 필요한지부터 정리하세요. 가장 쉬운 출발점은, CMDB가 인벤토리가 아니라 서비스 영향과 의사결정 기반이라는 점입니다.

Ingest: 어떤 소스 데이터를 CMDB에 넣을지, 어떤 CI를 생성할지 설계합니다.

Govern: 중복/누락/오래된 데이터를 막아 신뢰도를 유지합니다.

Insight: CMDB 데이터를 기반으로 문제 영향도, 변경 리스크, 자동 보고를 지원합니다.

학습 포인트: 먼저 해결하려는 운영 문제를 정하고, 그 문제를 지원하는 데이터만 CMDB에 담는 것이 실제 성공 전략입니다.

EXAM KEYWORDS
trustworthy CMDB, organizational buy-in, downstream impact, stale CIs, actionable insights

2. CSDM 구조와 도메인

HIGH

CSDM은 CMDB를 어떻게 나눌지, 어떤 관계를 쌓을지 알려주는 청사진입니다. 처음에는 도메인별 역할과 데이터 흐름을 이해하는 데 집중하세요.

Design & Planning: Business Application, Information Object, Capability를 정의해 비즈니스 관점을 정리합니다.

Service Delivery: Application Service와 Technical Service를 구분하고, 서비스 제공 경로를 모델링합니다.

Service Consumption: Business Service/Service Offering을 통해 소비 관점에서 서비스를 묶습니다.

Foundation: User, Group, Location 같은 공통 데이터가 전체 모델의 기준이 됩니다.

학습 포인트: CSDM은 표준 데이터 모델입니다. 실제 질문에서는 도메인 이름 대신 '무엇을 설명하는가'를 물을 때가 많습니다.

EXAM KEYWORDS
Design & Planning, Service Delivery, Business Application, Information Object, Service Offering, Foundation data

3. CI/Asset/클래스 모델링

HIGH

초보자는 먼저 CI와 Asset의 차이를 구분하고, 이미 있는 클래스 모델을 확장하는 흐름을 이해해야 합니다.

CI: 서비스 운영에서 사용하는 구성 요소를 나타내는 기술 객체입니다.

Asset: 구매, 비용, 수명주기 관점이 중요한 재무 객체입니다.

일반적으로 모든 Asset이 CI는 아니고, CI는 반드시 Asset이 아닙니다.

기존 CI Class Model을 먼저 확인하고, 없는 경우에만 신규 클래스를 만들어야 안전합니다.

문제 풀이 법칙: 관계 문장은 항상 '누가/무엇이 어떻게 연결되는지' 먼저 읽습니다.

EXAM KEYWORDS
Configuration Item, Asset lifecycle, parent class, child class, principal class, CI Class Manager

4. IRE: 식별(Identification)과 조정(Reconciliation)

HIGH

입력된 데이터가 어떤 CI를 가리키는지 먼저 찾고, 누가 최종 값을 쓰는지를 정하는 단계입니다.

Identification Rule: 새로운 데이터가 기존 CI와 같은 지를 판별하는 규칙입니다.

Duplicate CI: 하나의 실제 항목이 여러 레코드로 중복된 상태입니다.

Overloaded CI: 서로 다른 실제 항목이 하나의 레코드로 합쳐진 상태입니다.

Reconciliation Rule: 어떤 소스가 속성 값을 최종적으로 결정할지 우선순위를 설정합니다.

학습 포인트: Identification 먼저, Reconciliation 나중. 우선순위 숫자 방향을 반드시 확인하세요.

Import Sets/Transform Map 문제는 IRE 우회와 onBefore/CMDBTransformUtil 패턴을 연결해서 풀면 쉽습니다.

EXAM KEYWORDS
IRE API, identification rule, reconciliation rule, authoritative source, data refresh rule, CMDBTransformUtil, onBefore

5. Data Foundations와 거버넌스 도구

MID

어떤 품질 문제를 어떤 도구로 해결할지 빠르게 매칭하는 연습이 중요합니다. 도구 이름보다 '이 문제를 이렇게 개선한다'는 흐름을 기억하세요.

CMDB Health Dashboard: Completeness, Correctness, Compliance를 한눈에 보여주는 품질 대시보드입니다.

CMDB Data Foundations Dashboard: 플레이북 기반으로 단계별 개선 과제를 제안합니다.

CMDB Data Manager: Certification/Attestation과 Archive 정책을 통해 데이터 수명주기를 관리합니다.

De-duplication Dashboard/Template: 중복 CI를 찾아 정리하는 자동화 도구입니다.

학습 포인트: 품질 문제를 확인한 뒤, 적절한 거버넌스 도구를 연결하는 연습을 하세요.

EXAM KEYWORDS
3C, playbook, certification, attestation, archive policy, de-duplication, managed by group

6. 실전 문장 패턴 (영어 지문 대응)

CORE

영어 지문을 빠르게 해석하려면, '무엇을 묻는가'를 먼저 찾고 '어떤 개념을 쓸 것인가'를 연결해야 합니다.

자주 나오는 질문 프레임

recommended method / preferred way: 표준 거버넌스/모델 경로를 묻는 문제입니다.

choose all that apply: 옵션별 장점과 조건을 정확히 구분해 선택합니다.

which field / which tab / where can: 설정 위치나 메뉴를 묻는 문제로, 도구 이름보다 UI 흐름을 떠올려야 유리합니다.

authoritative source / priority / order: IRE 우선순위와 최종 값 결정 흐름을 해석하는 문제입니다.

질문 신호어 바로 떠올릴 개념 대표 오답 패턴
duplicate / stale / quality Health 3C, Data Manager, De-duplication 단순 스케줄 잡/BR로 해결 가능하다고 단정
ingest + prevent duplicate IRE 경유 적재, IntegrationHub ETL, onBefore 패턴 테이블 직접 적재를 권장 답으로 선택
ownership / assignment / group Managed by Group, Support Group 전파 경로 Approval Group/Change Group과 혼동
CSDM domain Design vs Service Delivery 구분 도메인 이름은 맞지만 객체 레벨이 다름

이 개념정리를 기준으로 퀴즈 해설에 연계 섹션과 영어 키워드가 자동 표시됩니다.
