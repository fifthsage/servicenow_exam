Discovery 핵심 학습 지도 · 초안

공식 명칭은 Certified Implementation Specialist – Discovery입니다. 아래 비중은 현재 페이지에서 직접 열리지 않는 최신 동적 Blueprint 대신, ServiceNow가 공개한 레거시 Exam Specification의 4개 학습 영역을 초안 기준으로 사용했습니다.

  • Operations: Command, Parse Variable, Parse File

  • Credential, Affinity, 오류·중복 문제 해결

CURRENT PRACTICE COVERAGE

Cloud Discovery · 수집 설계와 검증

수집 전 설계

  • Provider 계정·Subscription/Project·Region을 포함한 식별 Context를 정한다.
  • Cloud Object ID를 우선하고, Display Name·가변 IP만으로 동일 CI를 판단하지 않는다.
  • Native Pattern과 Service Graph Connector의 Resource·속성·관계 Coverage를 비교한다.
  • Service Account에는 승인된 Account·API·Read 권한만 부여한다.

운영 후 검증

  • Provider Inventory와 CMDB를 Account, Region, Resource Type별로 비교한다.
  • API 오류·Rate Limit·Pagination·실행 시간을 함께 점검한다.
  • 중복 CI, Reconciliation 충돌, Class Mapping과 관계 정확성을 확인한다.
  • 짧은 수명의 Resource는 Cloud 수명주기에 맞는 갱신·Retirement 기준을 적용한다.
Cloud API 호출 성공만으로 수집 품질이 보장되지는 않습니다. Coverage, Identifier, 관계, IRE 결과까지 대조해야 실제 운영에서 쓸 수 있는 CMDB가 됩니다.

시험에서 자주 섞이는 구분

Classification은 장치 유형과 접근 가능성을 판단하고, Identification은 CI를 고유하게 찾으며, Exploration은 상세 속성과 관계를 수집합니다.

Identification Rule은 같은 CI인지 판단하고, Reconciliation Rule은 어느 데이터 소스가 어떤 속성을 갱신할 수 있는지 결정합니다.

ECC Queue는 통신 운반 경로이고, Discovery Status는 실행 결과와 단계별 문제를 추적하는 출발점입니다.

최신 릴리스에서는 Pattern과 IRE 중심으로 학습하되, 레거시 Probe/Sensor 용어도 기존 구현과 문제 보기에서 만날 수 있으므로 개념 관계를 알아두세요.
