1. 플랫폼 탐색 기반 (Module 1)

Foundation

CSA의 출발점은 플랫폼 상호작용 도구를 빠르게 식별하고, 사용자 관점에서 어떤 UI가 어떤 목적에 적합한지 구분하는 것입니다.

학습 목표
Workspaces, Service Catalog, Dashboards, Lists, Forms, Knowledge Bases의 역할 분리
Employee Center의 구성 요소를 업무 시나리오와 연결
"어디에서 작업해야 하는가"를 문제 지문만 보고 판단
학습 블루프린트 카드
Blueprint Step A: UI 채널 매핑
Workspace—역할 기반 운영자 중심 처리 화면
Catalog/Portal—요청자 중심 셀프서비스 채널
List/Form—데이터 조회/편집의 기본 단위
Knowledge—해결 정보의 축적 및 재사용
시험 포인트
"직원 스스로 정보/서비스 접근" 시나리오면 Employee Center 우선
작업자(Agent/Fulfiller) 효율 문제는 Workspace가 정답일 확률이 높음

2. 인스턴스 구성 전략 (Module 2)

High

인스턴스 구분, 브랜딩, 플러그인 활성화, 스코프 이해는 CSA에서 반복 출제되는 운영 기본기입니다.

핵심 개념 맵
개념 핵심 의미 시험형 키워드
Baseline implementation 구성 전 기본 설치 상태 "초기 상태", "사전 구성"
Instance 조직별 독립된 단일 테넌트 환경 Production vs Non-production
Update Set 구성 변경 이동 패키지 개발→테스트→운영 승격
Application Scope 앱 간 접근 경계/격리 Globe 아이콘, 접근 제한
실습형 블루프린트
Theme Builder로 로고/색상/폰트 설정
브라우저 탭 라벨로 Dev/Test/Prod 시각 구분
플러그인 설치 시 데모 데이터 로드 여부 판단
종속 플러그인 확인 후 활성화 순서 검토
시험 포인트
추가 기능 활성화 경로: Plugin / Store / ServiceNow 요청
새 기능 실험은 개인 개발자 또는 비프로덕션 인스턴스 사용

3. 리스트/폼 구성 역량 (Module 3)

High

리스트, 필터, 폼 구성은 CSA 실무형 문제의 중심입니다. 필드/연산자/값의 논리와 개인화 vs 전역구성을 구분해야 합니다.

리스트 운영 체크
List Controls—뷰 전환, 대량 작업, 필터링
Column Options—열 단위 시각화/내보내기/레이아웃
Right-click Context—셀 값 기준 빠른 필터/태그
Dot-walking—참조 테이블 필드 확장 조회
폼 구성 블루프린트
요소 활용 목적 주의점
Section 필드 논리 그룹화 과도한 분할은 가독성 저하
Formatter Activity Stream 등 비필드 정보 표시 필드 값과 혼동하지 않기
UI Action 버튼/링크 기반 사용자 동작 정의 활성 여부와 조건 확인
Related List 연관 레코드 표시 레코드 저장 후 표시됨
시험 포인트
필터의 3요소는 Field, Operator, Value
Personalize List/Form은 개인 화면에만 적용
편집 가능한 동일 필드의 중복 배치는 데이터 문제를 유발할 수 있음

4. 데이터 관리 및 접근통제 (Module 4)

High

테이블 구조, 임포트 세트, ACL 평가, CMDB/Discovery 개념을 함께 묻는 통합 문제가 많습니다.

데이터 구조 블루프린트
Table - Record - Field - Value 계층 이해
System Dictionary, Tables and Columns, Schema Map 사용 목적 구분
sys_id(32자 GUID)와 Number Maintenance 역할 구분
Import Set 실행 흐름
Data Source—외부 원천 정의
Import Set Table—Staging 영역
Transform Map—소스-타깃 매핑
Target Table—최종 저장 위치
Coalesce—중복 생성 방지 키
보안 계층 및 ACL 평가
층위 핵심 제어 학습 포인트
사용자/그룹/역할 기본 인증/권한 역할 할당 구조
애플리케이션/모듈 메뉴 접근 제어 역할 기반 표시 제한
ACL/속성 테이블·필드 단위 권한 deny 우선, table.none/table.* 구분
시험 포인트
ACL은 거부 규칙이 허용 규칙보다 먼저 평가됨
Coalesce 미설정 시 재임포트 때 중복 레코드가 생성됨
CSDM 5.0 최신화: Application Service는 이제 **Service Instance**로 불리며, 총 7개 도메인 체계입니다.
CMDB 관계 분석은 Dependency Map/Service Mapping 시나리오와 연결됨

5. 셀프서비스와 자동화 (Module 5)

High

Knowledge, Catalog, Workflow Studio를 묶어서 이해해야 요청-승인-이행 전체를 설명할 수 있습니다.

셀프서비스 채널 맵
Employee Center: 직원 중심 통합 진입점
Service Portal: 카탈로그/지식/요청 처리 포털
Knowledge Portal: 문서 조회/피드백 중심
Knowledge 운영 블루프린트
User Criteria—Can Read/Contribute 및 Cannot* 우선 적용
Workflow—Approval Publish/Retire vs Instant Publish/Retire
Guided Setup—요구사항 기반 단계 설정
Catalog + Flow 핵심
구성요소 기능 지식 점검 포인트
Catalog Item 주문 가능한 개별 항목 주문 시 RITM/SCTASK 생성
Variable 주문 시 사용자 입력 수집 질문/옵션의 실체
Order Guide 관련 항목 묶음 주문 단일 요청 다중 품목
Flow (Trigger + Actions) 승인/알림/이행 자동화 Data Pill로 후속 단계 데이터 전달

6. 시각화·알림·생산성 향상 (Module 6)

Core

분석 결과를 공유 가능한 형태로 만들고, 필요한 사람에게 적시에 알리는 운영 루프를 학습합니다.

Visualization Designer 구성 축
Data, Type, Metrics, Presentation의 4축으로 설계
기존 시각화를 복제 후 수정하는 방식이 안전
Dashboard 위젯 공유로 팀 가시성 확보
Notification 블루프린트
When to send—삽입/업데이트/이벤트/스크립트 기반
Who will receive—사용자/그룹, 비활성 사용자 제외
What it will contain—메시지 본문 및 데이터
Force delivery/Mandatory—필수 알림 강제 정책
시험 포인트
시각화 재사용: Duplicate, Share, Export 3가지 동작 구분
Notification 설정 질문은 언제/누구/무엇 탭으로 정리하면 빠르게 해결

7. 스크립팅·업데이트 세트 (Module 7)

Core

클라이언트/서버 스크립트 구분과 Update Set 이동 절차는 실무와 시험 모두에서 필수입니다.

스크립트/정책 사용 기준
도구 목적 선택 기준
Client Script 브라우저 즉시 반응 UI 입력 반응, 실시간 검증
Business Rule 서버 측 데이터 처리 Insert/Update/Delete/Query 동작
UI Policy Mandatory/Visible/Read only 제어 스크립트 최소화가 목표일 때
Data Policy UI/Import 전반 데이터 무결성 채널 무관 일관 검증 필요 시
Update Set 블루프린트
원칙: Default 대신 Named Update Set 사용
절차: Retrieve → Preview → Commit
주의: Complete 처리 후 In-progress로 되돌리지 않기
한계: 데이터 레코드는 Update Set으로 이동되지 않음 (필요 시 Export XML)
충돌 방지: 생성 순서대로 커밋
시험 포인트
Update Set에 캡처되지 않는 대상은 데이터 레코드
애플리케이션 보호 메커니즘은 Application Scoping

8. 인스턴스 보안 운영 (Module 8)

Core

Shared Responsibility Model과 Security Center 활용은 운영 관점 CSA의 핵심 마무리 영역입니다.

Shared Responsibility 핵심
고객: 접근제어, 역할, 보안설정, 패치 일정, 데이터 보호 운영
ServiceNow: 인프라 보안, 플랫폼 제공, 규정 준수 기반 운영
암호화·로깅·보안센터
영역 핵심 포인트 지식 점검 축
Encryption At rest / In transit 모두 고려 2가지 암호화 유형 구분
Security Center Hardening, Scanner, Customer Actions, Metrics Admin / Security Center viewer 접근
Logging 인프라 로그와 고객 앱 로그의 접근 주체가 다름 모니터링 책임 주체 구분
Security Contacts Now Support 연락처 최신화 긴급 보안 커뮤니케이션 준비
시험 포인트
Scanner는 보안 설정 비교를 통해 취약 영역을 도출
Metrics는 위협 징후(예: 로그인 실패 급증) 모니터링에 활용

9. 시험 직전 체크리스트

각 항목을 소리 내어 설명할 수 있으면 모듈 1~8 학습 축이 정리된 상태입니다.

플랫폼/인스턴스
Baseline implementation, Instance, Plugin의 관계를 설명할 수 있다.
Application scoping과 Global scope 차이를 설명할 수 있다.
Dev/Test/Prod 구분을 UI 브랜딩으로 설정하는 이유를 설명할 수 있다.
리스트/폼/데이터
필터 3요소(Field, Operator, Value)를 정확히 말할 수 있다.
List personalization과 전역 레이아웃 변경을 구분할 수 있다.
Import Set에서 Coalesce가 없는 경우의 문제를 설명할 수 있다.
ACL 평가에서 deny 우선 규칙을 예시로 설명할 수 있다.
셀프서비스/자동화
Catalog Item 주문 후 생성되는 Request, RITM, Catalog Task를 구분할 수 있다.
Flow는 Trigger 1개 + Actions 1개 이상 구조임을 설명할 수 있다.
Data Pill과 Dot-walking의 데이터 전달 흐름을 말할 수 있다.
운영/보안
Update Set 적용 순서(Retrieve, Preview, Commit)를 기억한다.
암호화 두 유형(At rest, In transit)을 구분한다.
Security Center의 Hardening/Scanner/Metrics 역할을 설명할 수 있다.
최종 학습 루프
1회독: 이 페이지에서 개념 맵 정리
2회독: CSA 랜덤 문제 풀이로 지식 점검
3회독: 오답 노트로 약한 영역만 반복
시험 전: 체크리스트 전 항목을 5분 내 구두 설명
